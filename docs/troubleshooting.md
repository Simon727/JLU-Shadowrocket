# 排障指南

## 下载失败

先确认能访问工具的官方 GitHub Releases。需要代理时使用 `setup --download-proxy <自己的HTTP代理地址>`；该参数只影响下载，不改变系统代理。SHA-256 不符时程序停止，不执行该文件，也不自动删除文件。请检查网络或自行处理文件后重试。

## 进程刚启动就退出

- 运行 `prepare` 检查配置。
- 检查 `private/sing-box.log` 与 `private/cloudflared.log`，对外分享前遮去主机名、URL 和账户相关信息。
- 确认没有重复启动同端口实例。只关闭自己明确启动的那个窗口，不要结束整台电脑上所有同名程序。
- `web_port`、`vmess_port`、`metrics_port`、`check_port` 必须不同；默认18080-18083，全部仅监听回环地址。

## TCP有延迟，但网页打不开

1. 确认选中的是你本次部署的 `JLU-Campus`，全局路由为“配置”。
2. 确认已经下载并“使用”分流配置；只更新订阅不会更新路由。
3. 数据 → 日志 → 代理，查找 `yjs.jlu.edu.cn`。应指向 `JLU-Campus`，若为 DIRECT，检查规则顺序。
4. 在电脑运行 `check`。如果电脑端完整公网请求也失败，优先检查校内网络、Tunnel 和服务日志。
5. 如果默认配置能用、日常配置不能用，将 README 的精确域名规则置于国内直连规则之前。

服务端拒绝非允许目标。CONNECT方式的延迟测试可能访问一个未允许的测速站点而失败；TCP测试只判断入口端口，不能代替实际网页检查。不要为“测速变绿”随意放开所有域名。

## 临时入口可用，固定入口不通

先确认两个入口的后端、密钥和 WebSocket 路径相同，保留已验证的配置。可在手机可用节点中只修改地址、TLS SNI、WebSocket Host 为固定主机名，其他字段不动，再访问 OA。成功时重点比较原固定节点的导入参数、同名节点和规则实际引用；这时不能断言固定域名不可用。操作条件和订阅迁移注意事项见[固定域名对照](fixed-tunnel.md#临时入口可用固定入口却打不开时)。

如果重新导入又失败，查看这一次请求实际命中的节点，核对手机导出参数与服务端，并检查服务端请求处于哪个阶段。WS101 不是 VMess 或学校网站访问成功的证明；已经认证且目标出站可见时，也不能再将问题简单归为 UUID 错误。保存版本与参数后，可在启动窗口 Ctrl+C，再原样启动本实例；不要批量结束无关进程、删除 Tunnel 或换密钥。恢复后保留当前可用状态，根因未确定时不要宣称永久修复。

Shadowrocket 内部导出的 `obfsParam` 可能使用序列化存储，须结合编辑界面和实际数据流检查，不能看见 JSON 就断言 WS Host 错误。可选 `/subscription.txt` 为原生 VMess URI 订阅，保留同一令牌和参数；该格式本身的编码、鉴权测试通过，并不意味着它能解决所有断流问题。

## 能打开，但页面加载慢

先区分校园站点响应、Cloudflare 中转和手机页面资源加载。电脑端可以小量比较同一 OA 登录页的直连、临时入口和固定入口，记录首字节、总耗时与 TLS 校验。若两种中转耗时接近，不应仅凭主观感受更换固定域名。手机还会加载图片、脚本和业务接口，检查实际慢请求或失败目标后再调整；只补充已确认需要的具体学校域名，保持全局路由为“配置”。电脑 HTML 计时不能当作手机完整页面测速。

## 手机能握手，但加载几分钟不完成

用不含学校数据的固定大小测试分别检查 HTTPS 和 WebSocket 是否完整收到预期字节，并分多轮比较真实固定、Quick 入口。两条订阅若下发相同的固定节点，不是独立路径对照。保持电脑后端一致，避免将学校认证、VMess 与公网传输问题混在一起。

本次手机对照中固定数据路径多次只能收到部分随机字节后超时，而 Quick 完整通过；更换连接 IP、将固定隧道改为 QUIC 均未形成可靠修复。已验证的处理方式是[固定订阅 + Quick 数据通道](fixed-tunnel.md#固定订阅--quick-数据通道)，而不是继续让用户反复换名称或刷新到同一不稳定数据路径。

分离模式中订阅 URL 是固定域名，节点的地址/SNI/Host 是 Quick 域名，属于正确配置。重建数据隧道后刷新同一订阅，保留节点名和学校分流；不要把 Quick 节点手改为固定域名。此方式仍受 Quick 可用性与本机在线条件限制。

## 全局代理后微信不能用

这是仅代理学校目标的部署。将全局路由改回“配置”，使用专用规则；其他应用通过DIRECT或你自己的日常规则访问。

## 出现CAS统一身份认证页面

说明至少已经到达学校认证网站。请使用本人学校账号正常认证。此方案省去的是校外访问的WebVPN步骤，不能取消研究生、OA本身的业务认证。主动退出登录会使会话失效，之后重新认证属于正常情况。

## 只在同一热点下可以下载，但开VPN后内网节点超时

本项目的手机节点使用公网TLS443域名，不应填写校内电脑的私有IP或`127.0.0.1`。电脑网络变动时私有IP会变化，手机热点和隧道路由也可能相互影响。不要把电脑本机测试成功等同于手机网络已可达。

## 页面主体能打开，部分功能缺失

可能还有其他学校资源或接口域名。先通过日志确认实际目标，再在`private/config.json`的`allowed_domains`添加确实需要且有权使用的具体学校域名，重启并更新手机分流配置。不要使用通配符或把所有请求都放行。

## 重启后订阅失效

Quick Tunnel每次重建会更换临时主机名。使用本次启动输出的新链接，或配置固定域名。UUID和下载令牌会保存在`private/secrets.json`并复用，不会因正常重启自动重置。

如果使用长期 `named` 模式，先检查 `private/config.json` 的 `tunnel_mode`、`hostname` 及令牌文件是否正确。固定域名正常重启应沿用原链接；不要为恢复连接重新创建 Tunnel、删除 DNS 或更换密钥。

## 固定入口提示 TLS 错误、1033 或 502

- 先关闭手机 Shadowrocket 总开关，用本次固定链接下载，避免请求被当前分流送入仅允许校园域名的节点。
- TLS 错误：检查固定域名 DNS、证书覆盖和本机时间；优先使用根域下一级子域名。保持证书校验开启，不用 `allow insecure` 或 `curl -k` 掩盖问题。
- 1033：检查 Tunnel 是否健康、本机 cloudflared 是否仍在运行；仅显示导入链接不代表连接已建立。
- 502：核对 Published application 的 Service URL 指向实际 `web_port`（默认 `http://127.0.0.1:18080`），本地 HTTP 前端是否监听。不要填 sing-box 的 VMess 端口。
- 浏览器能打开登录页而 Shadowrocket 无法连接时，检查专用主机名是否被额外的交互式 Access 登录或验证挑战拦住。不要关闭整个域名的安全保护；先识别具体规则，仅为这个专用入口评估必要的调整。

详细配置见[固定域名部署](fixed-tunnel.md)。

## 怎样停止

在启动窗口按Ctrl+C。程序只停止本实例启动的子进程，不修改防火墙、不删除密钥和下载文件。电脑关机、休眠或离开可访问校园网站的网络后，手机访问会受到影响。
