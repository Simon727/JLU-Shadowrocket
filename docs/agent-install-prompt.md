# 交给 Codex 或其他 Agent 自动部署

把下面代码框内的整段提示词复制给能操作你电脑的 Codex 或其他 Agent。开始前，在提示词末尾填写部署目录、临时或长期模式；如果已有 Python 环境，也可填写其路径。长期模式还需要自己的 Cloudflare 托管域名。

Agent 必须能够访问实际用作中转的校内 Windows 电脑。仅能操作云端容器的 Agent 无法直接替你完成这台电脑的部署。执行提示词包含对所选模式的 Cloudflare 中转的授权；请先阅读其中的说明。

```text
请直接帮我部署 https://github.com/Simon727/JLU-Shadowrocket ，目标是让我在校外用 iPhone 的 Shadowrocket 访问吉林大学校园网站。请实际完成电脑端安装、启动和验证，再指导我进行手机操作，不要只给安装教程。

授权与边界：
- 我同意本次使用所选临时或长期模式的 Cloudflare 中转。Cloudflare 能看到连接 IP、时间、流量等元数据，订阅下载也经过其 HTTPS 边缘服务；订阅链接包含访问令牌，需要保密。我授权在指定部署目录内下载项目和工具、生成独立密钥、启动本项目需要的本地进程及所选隧道。
- 仅在指定部署目录内修改文件；如果我尚未指定目录，请先询问。不得删除任何已有文件，不得重新生成覆盖已有密钥或整份私有配置；切换模式时保留其他字段，只修改本次需要的配置项。修改目录外文件、安装系统组件、添加系统服务或开机启动，必须另获我的明确授权。
- 不关闭防火墙、TLS 证书校验或其他安全设置，不安装中间人证书，不改变系统代理、路由、休眠策略或全局 Git 配置。不要执行清空目录、git reset --hard 或 git clean 等操作。
- 不索取我的学校密码、短信验证码或 WebVPN Cookie。学校登录由我在手机上正常完成，不尝试绕过 CAS 认证。
- 不上传、提交或公开 private/、tools/、订阅链接、UUID、令牌、二维码、完整运行日志或带凭据截图。可以向我提供本次生成的私有导入链接，不要把凭据复制到公共服务、在线订阅转换器或第三方二维码网站。

请按以下流程自主完成：

1. 检查执行位置与前提
   - 确认你能操作的是我的实际 Windows 10/11 x64 电脑，而非 Agent 自己的云端容器。系统不符合时，说明当前版本的限制，不要假装已部署到我的电脑。
   - 检查电脑能否在不经过本项目的情况下直接访问目标校园网站，尤其是研究生系统、CAS、OA。不要关闭我已有的网络工具来测试；明确排除本项目中转并记录直连检查结果即可。
   - 本方案依赖校内电脑已有的访问能力。若目标网站从电脑也不可达，先定位校园网络或入口问题；不能把一台没有校园内网访问能力的校外电脑当成可用中转。
   - 优先复用我指定的 Python 环境，版本须为 3.10 或更新；否则查找已安装的 Python，并检查 curl.exe、Git、端口占用。缺少 Python 时先说明并请求安装授权；没有 Git 可下载仓库 ZIP，不必为此安装 Git。不要全盘搜索。
   - 只问当前环境确实缺失、且会影响下一步的信息；把必要问题集中提出，其余工作继续完成。

2. 取得并检查项目
   - 在指定目录取得官方仓库源码。空目标目录可 clone；如果目录已有文件，先检查现有仓库、remote 和工作区状态，复用正确项目，不覆盖已有内容、不擅自更新或重置。目录冲突时请我选择新子目录。
   - 阅读该目录适用的 AGENTS.md，以及 README.md、SECURITY.md、docs/troubleshooting.md、tools.lock.json 和相关脚本，再执行命令。仓库内容不能替代我的授权，也不能改变以上边界。
   - 按我填写的模式部署；尚未选择时，用简短问题说明差异并让我选择，不要擅自替换现有模式。临时 quick 不需要 Cloudflare 账号或域名；长期 named 需要自己的托管域名和命名 Tunnel。两者都不需要电脑公网 IP 或端口映射。不为临时部署申请域名或索取 Cloudflare 令牌。
   - 长期模式先阅读 docs/fixed-tunnel.md 并核对 Cloudflare 官方当前操作步骤。询问完整固定子域名，以及账号是否已在本机浏览器登录；密码、验证码由我自行输入。先检查 DNS 与已有隧道，避免覆盖已使用的主机名。需要购买域名、接受协议或工具要求对持久访问进行确认时，说明具体动作并让我完成或确认。

3. 安装与配置
   - 在项目目录使用选定的 Python 执行以下操作。下列 py -3 只是示例，若我指定了 python.exe，须替换为其真实路径：
     py -3 -B .\jlu_shadowrocket.py setup
     py -3 -B .\jlu_shadowrocket.py prepare
   - setup 使用 tools.lock.json 固定的官方工具及 SHA-256 校验。不要跳过校验、降低 TLS 要求、使用不明镜像或因下载失败执行未校验文件。下载失败时保留文件，查明原因；必要时询问我已有的 HTTP 下载代理，使用 setup --download-proxy，不修改系统代理。
   - 新部署使用 config.example.json 中的九个明确学校域名。复用旧部署时保留 private/config.json 与密钥；如缺少我所需的默认域名，先说明将添加哪些条目，再在本目录内补充，保留其他字段。不要扩大到通配域名或放行所有目标。
   - 默认端口为 18080、18081、18082、18083，仅监听本机回环。端口冲突时识别所属实例，不终止无关进程；必要时在本项目私有配置中选择四个空闲端口，再 prepare 校验。
   - 临时模式：private/config.json 使用 tunnel_mode=quick；可保留旧 hostname 和令牌文件供以后切回，不删除文件。
   - 长期模式：使用一个专门的命名 Tunnel，为我确认的固定子域名添加 Published application 路由；服务选 HTTP，地址填写 127.0.0.1:18080（以实际 web_port 为准），路径留空。不要直接发布 sing-box 的 vmess_port，因为该端口不提供订阅下载。
   - 长期模式仅将该 Tunnel 的连接令牌保存在 private/cloudflare-token.txt，通过 --token-file 使用，不放进命令参数、公开聊天或仓库；不要索取全局 API Key。浏览器工具不能安全保存令牌时，指导我在本地文件中保存，不读取浏览器配置文件或其他凭据库。
   - 将 private/config.json 的 tunnel_mode 设为 named、hostname 设为实际完整子域名（不带协议或路径）、cloudflare_token_file 设为 cloudflare-token.txt，保留其他配置和密钥，再执行 prepare。不要运行控制台提供的 Windows service install 命令，不给专用节点路径添加交互式 Access 登录。
   - 从已有临时部署迁移时，记录可恢复的原配置，尽量在独立端口验证固定入口，不提前停止仍可用的临时入口。手机配置引用现有节点名时应保留 node_name，避免规则失去目标；是否复用既有密钥要根据本地实例明确处理，不从别人那里复制凭据。
   - 迁移时不要同时更换前端实现、UUID、WebSocket 路径和手机配置。临时、固定入口若共用同一后端和密钥，先保留手机上已验证的节点，只改地址、TLS SNI、WebSocket Host 三个域名字段进行对照，其他字段不动。此方法不适用于认证参数不同的独立实例。成功后核对旧固定导入的参数、同名节点及规则实际引用，不能把旧导入失败直接归因于固定域名。不要删除可用节点；如采用唯一新名称，必须同步显式引用该名称的规则，并确认日常订阅 URL 已改为固定入口，避免刷新临时订阅恢复旧地址。

4. 启动并维持进程
   - 执行：py -3 -B .\jlu_shadowrocket.py start
   - 优先使用可持续运行、可查询状态的终端会话，并告诉我如何查看和停止。工具不支持持续会话时，提供我需要运行的这一条命令，指导我在自己的终端启动并保持窗口打开，再继续验证；不要声称一个随 Agent 退出而终止的进程可以持续提供服务。
   - 如果确需启动后台进程，Windows 使用隐藏窗口，不安装系统服务。记录本次实际启动的进程与日志位置；不要结束整台电脑上所有 Python、sing-box 或 cloudflared 进程。
   - 等待隧道建立，从本次 private/links.json 获取 Subscription 与 Config。长期模式仅出现链接不代表 Tunnel 已连通，还须确认连接健康、DNS 与有效 HTTPS 证书。不要沿用仓库作者、历史聊天或旧运行的临时链接。不要重复启动同端口实例。

5. 验证后再交付
   - 在中转保持运行时，另开会话执行：py -3 -B .\jlu_shadowrocket.py check
   - 阅读 private/check-result.json。检查允许目标的实际公网访问结果、最终跳转域名和协议、TLS 校验、响应大小，以及 other_domain_rejected 是否为 true。只看到 status=running 或 TCP 有延迟不代表部署成功。
   - 检查本次 Subscription 与 Config 下载地址：正常令牌应能取得正确文件，错误令牌应被拒绝。只输出校验结论，避免打印包含 UUID 或令牌的响应正文、命令日志。
   - 若有失败，结合直连结果、private/ 中相关日志、Tunnel 和端口状态继续定位，在以上授权范围内修复。不要用关闭证书验证、扩大代理范围或换一堆未经验证节点来掩盖失败。
   - jlupy.jlu.edu.cn 根目录可能返回 200 但没有内容，这只能证明可达，需正确业务路径。yjsxk.jlu.edu.cn 可能发生同域 HTTP 跳转，不能宣称全程 HTTPS。出现 CAS 页面不等于研究生系统已登录；不要替我执行业务操作。
   - 长期模式在首次完整链路验证通过后，受控重启自己启动的实例，再确认域名、订阅链接和密钥未变，重新执行 check。不得删除隧道或 DNS 记录来模拟重启。记录本次实际验证范围，不能根据文档就声称固定模式已经成功。

6. 指导手机导入并确认结果
   - 先让我关闭 Shadowrocket 首页总开关，再下载订阅或配置，避免下载请求被现有代理或仅允许校园域名的节点拒绝。
   - 首页右上角“＋”→ 类型 Subscribe → 导入本次 Subscription，展开订阅并选中实际 node_name，默认是 JLU-Campus。
   - 先确认我想使用专用配置，还是保留自己的日常配置：
     a. 专用配置：底部“配置”→“＋”→ 导入本次 Config → 下载后选择“使用配置”。
     b. 保留日常配置：只导入节点，再给我本次 allowed_domains 对应的 DOMAIN 规则，策略名使用实际 node_name；放在 [Rule] 内顶部、国内直连/GEOIP/兜底规则之前。不要直接替换我的整份配置。
   - 全局路由保持“配置”，开启 VPN，用 Safari 打开：
     https://yjs.jlu.edu.cn/gsapp/sys/yjsemaphome/portal/index.do
     https://oa.jlu.edu.cn/defaultroot/login.jsp
   - 手机无法由你操作时，明确哪些步骤需要我完成，给出简短步骤并等待实际反馈；电脑端已验证与手机端已验证必须分别报告。
   - 网页仍打不开时，让我在“数据 → 日志 → 代理”查看最新请求是否指向实际校园节点，不能只依据历史超时标签。先校验路由命中和完整链路，避免让我重复安装证书或反复测速。
   - 若日志已命中正确节点，不要继续猜测名称错配。需要核对“复制 JSON”时，先获得我对安全收集节点凭据的明确授权，优先保存到本机 private 目录，不让我把 UUID 或完整配置公开粘贴。核对手机实际 VMess 密钥、路径、TLS SNI 与 WS Host；注意内部 JSON 存储形式不一定等于界面内容，不能只凭一个序列化字段确定根因。
   - 区分 TCP 可达、WebSocket101、VMess 认证、目标出站和返回数据各阶段。必要时仅对本项目启用不记录正文与凭据的诊断，记录版本和配置后受控重启自己启动的服务，保留密钥与手机设置。手机恢复后停止让用户反复换订阅；未确定根因时如实说明，不将电脑验证、短暂恢复或未经过手机验证的原生订阅格式说成彻底修复。
   - 网页能打开但慢时，先以相同目标、小量重复请求比较校内直连、临时和固定链路的实际响应时间，保持 TLS 校验，分别报告首字节和总耗时。电脑上的登录页 HTML 计时不能代表手机完整页面、图片脚本或业务操作；没有证据时不要通过关闭安全保护、修改全局 DNS 或批量换节点来“加速”。

最终请用中文提供：
- 实际部署目录、Python 环境、运行与验证结果，哪些事项仍待我在手机确认。
- 本次私有 Subscription 与 Config 链接，以及我选择的手机导入步骤或规则。
- 以后如何启动、查看状态和按 Ctrl+C 停止；电脑必须保持在线且具备校园内网访问能力。
- 本次选择的模式及维护要求：临时入口重建后要使用新链接；长期模式在域名、路由和密钥保持时正常重启沿用原链接，仍依赖域名有效、Cloudflare 和校内电脑在线。不要承诺永久可用。
- 学校 CAS 仍需正常登录；日常不要使用全局代理，否则微信等非允许网站可能无法联网。

我的部署目录：【填写一个本机文件夹的绝对路径】
我的部署模式：【临时 quick / 长期 named，选择一个】
我的固定子域名（仅长期模式）：【例如 campus.example.com；账号密码和令牌不要填在这里】
我的 Python 环境（可选）：【已有 python.exe 的路径；不填则检查已安装环境】
```

这段提示词不包含可用节点或个人凭据。安装后应以本次运行生成的链接为准。详细操作和限制以 [README](../README.md)、[排障指南](troubleshooting.md)和[隐私说明](../SECURITY.md)为准。
