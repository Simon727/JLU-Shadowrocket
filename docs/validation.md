## 自动化测试

`python -B -m unittest discover -s tests -v` 当前共11项通过，覆盖：

- 不同安装独立生成密钥，正常重启保留已有密钥。
- 拒绝非学校域名、通配符、配置注入和无效端口。
- 校内出站默认只允许明确目标，兜底拒绝，不依赖Cookie或测试证书。
- 下载鉴权、错误令牌404、无缓存响应及分流规则不包含凭据。
- WebSocket升级时保留已跟随HTTP头部发送的二进制帧，双向转发不丢数据。
- 归档文件不能向工具目录外写文件。
- 固定Tunnel令牌通过文件读取，不能指向private目录外，命令参数不包含令牌内容。
- 可选原生 VMess URI 订阅的鉴权、纯域名 WS Host、SNI、带特殊字符路径和名称的编码往返；保留 YAML 下载兼容性。
- auto/http2/quic 的参数选择与令牌文件保护、第五个端口的冲突检查、固定下载主机与 Quick 数据主机分离。
- 分离模式的本地真实 HTTP 启动、固定链接/Quick 节点/runtime 产物、两条隧道命令及安全停止；该启动测试使用外部进程假实现，不冒充真实 Cloudflare 测试。

## 固定命名 Tunnel 与重启验证

使用本仓库程序与自己的 Cloudflare 托管域名创建真实命名 Tunnel，Published application 路由指向本机回环 HTTP 前端；连接令牌仅由 `private/` 中的文件提供，不安装 Windows 系统服务、不修改防火墙或系统代理。

2026-10-24 实测结果：

- 固定入口的节点订阅与分流配置下载均返回 HTTP200，HTTPS 证书校验通过；订阅中的主机名、节点名、UUID 和 WebSocket 路径与该实例一致。
- 错误下载令牌返回404；分流配置含全部9个精确域名规则及 `FINAL,DIRECT`，没有包含订阅令牌或节点 UUID。
- `check` 经固定公网域名、TLS、VMess 和校内电脑访问9个允许目标，最终响应均为200、最终 HTTPS 校验均通过，非允许域名请求被拒绝。`jlupy` 的空响应和选课站点的 HTTP 中间跳转限制仍适用。
- 停止本次固定实例后原样重启，再次通过下载与9个目标检查。对比重启前后私有配置、密钥文件、下载链接及 Tunnel 令牌文件的 SHA-256，全部一致。

本节只发布无凭据的验证结论，不发布实际固定域名、Tunnel ID、订阅链接、令牌、密钥、哈希值或原始日志。固定地址的可持续使用仍取决于域名有效、Cloudflare 配置与校内电脑在线；不等同于自动开机启动或永久可用。

## 2026-10-25：手机固定入口对照与耗时

为排除多项迁移变化，将临时和命名 Tunnel 指向同一个原型 Go HTTP 前端及同一个 sing-box 后端，复用原型已验证的 UUID、WebSocket 路径和学校分流配置。该 Go 前端属于原型，与仓库独立发布的 Python HTTP 前端不同。

- 用户确认临时对照节点可在手机打开 OA。
- 用户关闭 VPN，仅将该可用节点的地址、TLS SNI、WebSocket Host 改为固定主机名，保留名称、密钥、路径、端口及配置后，确认固定入口也可打开 OA，但感觉较慢。
- 这证明当时固定域名具备手机访问能力。旧固定节点失败与该成功条目之间仍可能涉及导入参数、缓存或规则引用差异，尚未确定唯一根因；不据此宣称修复了 Cloudflare 网络或安全策略。
- 同一电脑对 OA 登录页 HTML 各请求三次，均返回200且 TLS 校验通过。总耗时中位数：校内直连1.28秒、固定入口1.72秒、临时入口1.73秒。固定与临时入口在这组小样本中接近；这不代表手机完整页面加载速度，也不构成长期性能保证。

未验证此次原型固定入口的全部学校业务、登录后的操作或独立 Python 发布版的手机迁移。公开记录仅包含结论，不包含个人域名和凭据。

### 后续重导入失败与服务恢复

上述手改成功后，用户重新导入固定订阅又遇到 OA 停止响应，因此不能把该对照记录解释为订阅问题已经彻底修复。手机请求日志显示命中正确校园节点；经用户授权收集到本机的节点导出中，VMess 密钥、路径、服务器地址和 SNI 均与服务端一致。WS Host 内部字段采用 JSON 表示，但手机编辑界面显示单独域名，尚不能据此认定格式错误。

为记录连接阶段，保留域名、UUID、路径和学校规则，受控重启原型服务，启用仅记录握手状态、字节数和目标域名的诊断；同时原型前端新增可选原生订阅端点，原有 YAML 端点继续保留。服务端观察到手机 WS101、VMess 认证成功、向 OA 的443端口出站，以及双向数据。用户在不更新订阅、不修改手机参数的情况下确认 OA 恢复访问。

这次恢复发生在服务重启后，未隔离出唯一根因，也未验证长期稳定性。不能归因于节点改名、Host 格式修复或原生订阅切换；用户本次未切换原生格式。独立发布版的原生端点已通过8项测试中的相关编码与鉴权检查，不应表述为完成该手机环境的实际导入验证。

### 反复卡顿后的随机数据对照与当前交付

重启后的恢复随后再次失效。为区分公网传输、VMess 和学校业务，在同一后端加入令牌保护的测试，每个入口分别执行5轮 HTTPS、WebSocket，每项传输128 KiB随机字节，不访问学校系统。

| 手机路径 | 测试项 | 超时项 | 说明 |
| --- | ---: | ---: | --- |
| 固定入口，HTTP2 | 10 | 5 | 包括 WebSocket 只收到80 KiB即停止 |
| 对应真实 Quick 入口 | 10 | 0 | 各项完整传输 |
| 固定入口，改为 QUIC | 10 | 6 | 仍存在部分数据停止 |
| 对应真实 Quick 入口 | 10 | 0 | 各项完整传输 |

更换固定入口连接 IP 未恢复手机 OA，未将其发布为修复。这里证明的是该环境下两条路径的实际传输差异，不确定故障属于哪一运营商或 Cloudflare 内部组件，也不推广为其他环境的通用结论。

此前临时下载地址曾因共享同一节点元数据而下发固定节点，已纠正为独立 Quick 数据节点；用户确认真实 Quick 节点能打开 OA。随后固定订阅改为下发相同 Quick 节点，两个下载地址的内容经过逐字节比较一致；用户将已可用订阅的 URL 改为固定地址、更新后确认 OA 可打开。

当前交付是固定订阅与 Quick 数据分离。电脑实测同时通过固定订阅/配置的 HTTPS 下载、Quick 数据通道的九个校园入口及非允许域名拒绝。原型仍使用 Go 前端；通用 Python 程序新增同等分离选项，完成上述本地测试，未将原型结果说成对每位使用者的独立手机环境均验证通过。Quick 数据域名会在重建后变化，需刷新同一固定订阅，仍无可用性保证；没有宣称固定数据链路已修复。
